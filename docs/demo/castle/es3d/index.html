ILake

The lake is written, then drawn

The waterfall is one sweep along a path, and the spray is a loop. ES3D keeps those words in the file. glTF keeps the triangles they become, frozen at the detail chosen when the file was exported.

  • One description places every tree. glTF stores the mesh that description becomes.
  • Detail follows the screen. Come closer and ES3D cuts a finer shape. A glTF mesh stays at the triangles it shipped with.
  • The same flight. Both pages draw 54,787 objects, the same lights and the same path.

IIIGate

The portcullis rises with the page

Its motion is tied to your scroll. In the ES3D file that is one attribute you can read. In the glTF file the same rise is an animation curve packed into the binary.

IVCourt

A forest from a single seed

The violet tree is swept boughs and a canopy scattered by a seed. The wood around the court is that idea, repeated. Export it to glTF and the seed is gone: only one forest of finished leaves remains.

  • Change the seed and the wood moves. The arrangement is a number in the ES3D file.
  • Shapes, until you draw them. Roofs and boughs stay descriptions. Triangles appear when the browser needs them.
  • A smaller file. This world is 64 KB of text. The glTF binary of the same castle is 4,067 KB.

VStair

Sixty-six steps, one instruction

The stair is a repeat and the rail is one helix. ES3D writes the rule, and the tower climbs as far as the count says. glTF writes out every tread that rule produced.

  • Repeat, rather than copy. Sixty-six steps are one step and a number in the file.
  • A curve, kept as a curve. The rail is swept along a helix. glTF stores the segments that sweep produced.
  • The flight is in the file. The camera path sits beside the castle, and both pages follow it.
