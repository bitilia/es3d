# ES3D benchmark results

Generated by `npm run bench` on 2026-10-07. Node 22.22.0, Intel(R) Xeon(R) Processor @ 2.80GHz (4 threads), linux x64. ES3D reader in JavaScript only (--no-wasm).
OBJ and GLB are exported from the compiled ES3D scenes at level of detail 0, so every format holds the same triangles.
Sizes: gzip level 9, brotli quality 11 (quality 9 above 2 MB). Times are medians in milliseconds after a warm-up run.

**Ready** = parse + scene build + mesh generation: everything needed for the GPU upload is in memory. For glTF read by three.js: GLTFLoader has built its scene of BufferGeometry. For *ES3D (cached)*: parse + build + reading the meshes an earlier load stored (geometry cache, here on disk; in browsers IndexedDB).
**GPU data** = unique vertex/index data (32 B per vertex, 4 B per index) + 64 B per instance in this renderer.
