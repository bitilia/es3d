The converter turns SVG, OBJ, STL, STEP and glTF into ES3D in the browser. ES3D Studio shows the scene as you type.

A 3D scene you can read

ES3D (Extensible Scalable 3D) is a file format for 3D scenes. It does for a scene what SVG does for a drawing. The file describes the objects. A rounded box here. An outline extruded into a solid there. Two thousand trees on a hill. The viewer builds the triangles, at the detail the screen actually needs. A forest fits in under a kilobyte, and a text editor is enough to write it.

You can try that here without installing a plugin. There is a converter for files you already have, an editor that runs in the browser, and the specification.

What can I do here?

  • Convert a file. SVG, OBJ, STL, STEP or glTF to ES3D, and ES3D back to glTF, OBJ, STL or STEP. The work happens in your browser. Nothing is uploaded.
  • Open ES3D Studio. Write on the left, watch the scene on the right, as you type.
  • Model something low-poly. Type points in 3D, join them into flat planes and paint each one. The ES3D Modeller saves the model as polygons.
  • Look at the examples. Thirteen scenes, from a rotating cube to a city of 7,300 buildings.
  • Open the Demo Sites. Ashby, Parcel, Spoke and Helio are small sites built with the library. Each one shows the size of its file.
  • Read the specification and the element reference. Papers and posts include Why ES3D came to be and Making the Web 3D, both from the founder, and a short of the castle demo, Making the web lighter.
  • Get the code. A JavaScript library, a command-line tool and the source, under the Apache License 2.0.

A tiny example

<es3d version="1">
  <defs>
    <group id="tree">
      <cylinder radius="0.15" height="1.2"
        position="0,0.6,0" color="#6d4c41"/>
      <cone radius="1" height="2.4"
        position="0,2.4,0" color="#2e7d32"/>
    </group>
  </defs>
  <scatter count="2000" radius="60"
           seed="7" randomScale="0.7..1.3"
           randomRotation="0,0..360,0">
    <use ref="tree"/>
  </scatter>
</es3d>

That is 2,000 trees. The trunk and the cone are defined once. <scatter> places the copies with a seeded generator, so every viewer puts every tree in the same spot.

About 400 bytes. The same forest as OBJ is tens of megabytes, because OBJ has to list every triangle of every tree.

The renderer turns each shape into triangles at four levels of detail, then draws the copies with a handful of instanced calls.

Does it actually save space?

Measured with npm run bench. Each format holds the same triangles. Sizes are gzip-compressed.

SceneTrianglesES3DglTF (GLB)OBJ
Primitive test scene44,9361.2 kB654 kB653 kB
Forest (7,401 instances)1.94 M0.6 kB187 kB24 MB
City (10,926 instances)8.7 M0.7 kB174 kBnot written
Scanned mesh (no structure)81,920704 kB744 kB *1.31 MB

* quantized glTF. ES3D is smallest when a scene is built from shapes, paths and repetition. A scan is stored as a mesh, so it lands near the size of glTF.
