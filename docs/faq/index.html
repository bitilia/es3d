Frequently asked questions

What is ES3D?
A file format for 3D scenes that describes how to build the geometry, instead of listing the finished triangles. Boxes, spheres, SVG path outlines extruded or turned on a lathe, tubes swept along curves, gears, copies placed by repeat and scatter rules. The viewer creates the triangles, at the level of detail the screen needs. ES3D stands for Extensible Scalable 3D.
How is it like SVG?
You can read it and write it by hand. Shapes are elements with attributes. Outlines use SVG's path commands (M L H V C S Q T A Z). Transforms are written the SVG way. <defs> and <use> work the same way, and materials are inherited the way fill is. Two differences matter: it is 3D, and the y axis points up.
Why not just use glTF?
glTF carries finished meshes. ES3D describes a scene made of shapes and repetition: diagrams, technical models, architecture, generated worlds. Those files can be hundreds or thousands of times smaller. A scan is stored as a mesh, so it stays about the size of the original.
Can I convert my existing files?
Yes, with the converter. SVG drawings become real ES3D shapes, because their outlines are extruded. STEP solids from CAD software become ES3D shapes too: boxes, extrusions, cylinders, spheres, tori and revolves, or face by face paths and revolves, with exact arcs. Only free-form (NURBS) faces, which ES3D has no element for, are tessellated. OBJ, STL, glTF and tessellated STEP become <mesh> elements, about as large as the original. The other direction is glTF, OBJ, STL and STEP, so a slicer or a 3D program can open the result.
Does the converter upload my files?
No. It is JavaScript in your browser. The files are read, converted and saved on your own computer.
Which browsers work?
Any current browser with WebGL2, which is nearly all of them, on computers and on phones. If the browser also has WebGPU, the renderer uses that. Both draw the same picture. There is nothing to install.
Does it work on my phone?
Viewing and converting, yes. Drag with one finger to turn a scene, and pinch to zoom. Writing scenes in ES3D Studio is easier with a keyboard and a larger screen.
How fast is it?
On a PC with an RTX 5060 Ti the forest draws in 1.4 ms with ES3D's own level of detail, and in about 8 ms when three.js draws every triangle of the same scene from glTF. A Galaxy S25+ and a Motorola moto g54 5G are slower and the gap is wider. A scanned mesh is the other way round: there is nothing to simplify, and glTF is ready first. The figures are the median of ten passes, on the home page and in the full tables.
What does "extensible" mean?
An element whose name starts with x- is an extension. A viewer that does not know it skips it and warns. Every other unknown element or attribute is an error, so a typo is never quietly ignored. Documents carry a version number. The rules for later versions are in the specification. There is one version 1, not a stack of profiles.
What can't ES3D do?
Version 1 has no skeletal animation, no morph targets, no physics and no text. Animation only moves, turns and scales things. Materials are a small physically based set: colour, metallic, roughness, opacity, emission, textures. The attribute is still named color. The file also has no script. It is a scene, not a program.
Is it free?
Yes. The specification, the library, the tools and this site are free software under the Apache License 2.0. The source is on GitHub.
I found a bug. Where do I report it?
Please open an issue on GitHub. If a file does not load, attach the file (or the smallest piece that still fails) and the error message, including the line and column.

What SVG got wrong, and what we are not copying

SVG became the vector format of the web, but the first decade was rough. A few of those failures are specific enough that a new format can just refuse them.

  • It needed a plugin, and the biggest browser ignored it. In 2000 the practical way to see SVG was Adobe's viewer, a browser add-on. Internet Explorer 6, 7 and 8 never implemented SVG, so the format sat out the years when Flash was what people actually shipped. ES3D's reference renderer is part of this site. WebGPU is used when the browser has it. WebGL2 is the fallback. If both are missing, you still have the text file.
  • The spec split into profiles, and one of them never shipped. SVG Tiny 1.1, Tiny 1.2, Basic, and a Full profile that did not become a Recommendation left authors guessing which subset a phone or a browser had. Version 1 of ES3D is one set of elements. Compact syntax and JSON are spellings of that same tree, not smaller dialects that drop features.
  • The spec listed features browsers then refused. Filters arrived late and unevenly. IE9 implemented SVG and declined SMIL animation. Chrome later deprecated SMIL too. SVG Fonts were specified and then dropped. SVG 2 marked further features "at risk" and removed them. The public text here matches what the reference renderer actually does. Animation is a transform tween (move, turn, scale). It is not SMIL, and it is not a promise of a second animation system.
  • One XML mistake blanked the picture. A missing xmlns, or a single well-formedness error, made Mozilla show an XML error page instead of the graphic. ES3D does not require a namespace. If you paste xmlns in anyway, it is ignored. Errors name a line and a column. Studio keeps the last valid scene on screen and marks it stale, rather than going blank.
  • The file type and the gzip extension confused servers. Browsers wanted image/svg+xml and often refused anything else. .svgz was gzip under a special extension, and servers regularly gzipped it a second time or sent the wrong headers. An .es3d file is UTF-8 text. Until a media type is registered, text/plain is fine, and you can still read it. Compression is .es3d.gz, an ordinary gzip file. There is no .es3dz.
  • An "image" could be a program. SVG can carry script, external resources, and (through a DTD) entity declarations. That last one is the billion-laughs trick: a small file expands into a huge one. Treating the file as a picture then became an XSS problem, and the W3C later had to define separate secure modes depending on whether the SVG was an <img>, a background, or a document. ES3D has no script and no event handlers. The markup parser accepts only the five predefined entities. A DOCTYPE is ignored, so it cannot declare more. The SVG importer expands simple Illustrator-style entities once, refuses nested expansion, and stops if the expansion grows large.

The interesting part of SVG, for this project, was the other half: a text file, a small set of shapes, paths you can copy between tools, and defs/use. That is the part ES3D keeps.

Links

Related formats and specifications:

  • SVG 2 (W3C). The 2D format ES3D borrows path syntax from. The early history is in the W3C note Secret Origin of SVG.
  • SVG Integration (W3C). The later attempt to say which SVG features must be turned off when the file is used as an image.
  • glTF 2.0 (Khronos Group). The transmission format for finished 3D meshes.
  • Web3D Consortium. Home of X3D and VRML, the older declarative 3D formats for the web.
  • OpenUSD. Pixar's Universal Scene Description.
  • WebGPU (W3C) and WebGL 2.0 (Khronos). The two graphics interfaces the ES3D renderer uses.
  • Wavefront OBJ, STL, STEP (ISO 10303-21) and VRML on Wikipedia.
  • RFC 6838. How media types such as model/vnd.es3d are registered.
